Mini Round 4 Notes

1. Program

A program is a file that contains instructions.

Example:
hello.c is a program.


2. Process

A process is a program that is currently running.

Example:
When we run ./hello, it becomes a process.


3. PID

PID means Process ID.

It is the unique ID of a process.


4. PPID

PPID means Parent Process ID.

It is the ID of the parent process.


5. fork()

fork() creates a new child process.

After fork(), there are two processes:
parent process
child process


6. fork() return value

pid < 0:
fork failed

pid == 0:
current process is the child process

pid > 0:
current process is the parent process


7. getpid()

getpid() returns the PID of the current process.


8. getppid()

getppid() returns the PID of the parent process.


9. wait(&status)

wait(&status) makes the parent process wait for a child process to finish.

It also stores the child's exit status in status.


10. Common mistakes

Wrong:
getid()

Correct:
getpid()


Wrong:
A process is a program that currently running.

Correct:
A process is a program that is currently running.


Wrong:
creats

Correct:
creates

Process Extra Notes

1. exit status

exit status means the code returned when a process finishes.

Example:
_exit(42)

This means the child process exits with status code 42.


2. wait(&status)

wait(&status) makes the parent process wait for a child process to finish.

It also stores the child's exit status in the variable status.


3. WIFEXITED(status)

WIFEXITED(status) checks whether the child process exited normally.

Simple meaning:
Did the child exit normally?


4. WEXITSTATUS(status)

WEXITSTATUS(status) returns the exit status of the child process.

Simple meaning:
What exit code did the child return?


5. Example

Child:
_exit(42)

Parent:
int status;
wait(&status);

if (WIFEXITED(status)) {
    printf("Exit status: %d\n", WEXITSTATUS(status));
}

Output:
Exit status: 42


6. Why are WIFEXITED and WEXITSTATUS uppercase?

They are uppercase because they are macros.

Many C macros are written in uppercase.

Examples:
SIGINT
SIGQUIT
WIFEXITED
WEXITSTATUS


7. macro

A macro is a predefined replacement rule in C.

It is processed before compilation.

Example:
#define PI 3.14

Then:
area = PI * r * r;

is treated like:
area = 3.14 * r * r;


8. Header file

To use wait, WIFEXITED, and WEXITSTATUS, include:

#include <sys/wait.h>


9. Simple memory

wait(&status)
= wait for child + get child's exit status

WIFEXITED(status)
= checks if the child exited normally

WEXITSTATUS(status)
= gets the child's exit code

Mini Round 4.4 Notes

1. pid_t pid = fork();

This creates a new child process and stores the return value in pid.


2. fork() return value

pid < 0:
fork failed

pid == 0:
current process is the child process

pid > 0:
current process is the parent process

Important:
In the parent process, pid is the child's PID.


3. perror("fork")

perror("fork") prints an error message if fork() fails.

Example:

if (pid < 0) {
    perror("fork");
    return 1;
}


4. getpid()

getpid() returns the PID of the current process.


5. getppid()

getppid() returns the PID of the parent process.


6. Child process part

if (pid == 0) {
    printf("Child PID: %d\n", getpid());
    printf("Parent PID: %d\n", getppid());
    _exit(42);
}

Meaning:
The child prints its PID and parent PID.
Then it exits with status 42.


7. Parent process part

else {
    int status;
    wait(&status);

    if (WIFEXITED(status)) {
        printf("Exit status: %d\n", WEXITSTATUS(status));
    }
}

Meaning:
The parent waits for the child.
Then it checks whether the child exited normally.
Then it prints the child's exit status.


8. Important mistake

Wrong:
In the parent process, fork() returns the parent's PID.

Correct:
In the parent process, fork() returns the child's PID.


9. Very important memory

pid == 0:
child process

pid > 0:
parent process, and pid is the child's PID

wait(&status):
used by parent

_exit(42):
used by child

Mini Round 4.5 Notes

1. Output before fork()

Any printf before fork() prints once.

Example:
printf("A\n");
fork();

A prints once.


2. Output after fork()

Any printf after fork() usually prints twice.

Reason:
After fork(), there are two processes:
parent process
child process

Both continue from the next line after fork().


3. Example

printf("A\n");
fork();
printf("B\n");

Output:
A
B
B


4. Parent and child branches

pid_t pid = fork();

if (pid == 0) {
    printf("Child\n");
}
else {
    printf("Parent\n");
}

Output:
Child
Parent

or:
Parent
Child

Reason:
pid == 0 is the child process.
pid > 0 is the parent process.
Without wait(), the order is not fixed.


5. Important correction

Wrong thinking:
After fork(), only the child continues.

Correct:
After fork(), both parent and child continue.


6. wait(&status)

wait(&status) makes the parent wait for the child to finish.


7. Output with wait

pid_t pid = fork();

if (pid == 0) {
    printf("Child\n");
    _exit(0);
}
else {
    int status;
    wait(&status);
    printf("Parent\n");
}

Output:
Child
Parent

Reason:
The parent waits until the child finishes.
So Child prints before Parent.


8. Without wait()

Order is not fixed.

Possible:
Parent
Child

Also possible:
Child
Parent


9. With wait()

Parent waits for child.

So:
Child first
Parent second


10. Common mistake

If you write:

wait(&status);

you must declare status first:

int status;
wait(&status);
